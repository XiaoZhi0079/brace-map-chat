# 子会话上下文摘要：备选设计

> 状态：已完成方案收敛。背景摘要固定使用完整父节点会话，引用原文仍由用户精确选择。

## 1. 已确认的产品约束

- 一个节点代表一轮独立的、多轮专题会话，而不是单条消息。
- 节点采用严格的“单父、多子”树结构。
- 子节点只继承直接父节点的信息，不递归携带完整祖先会话。
- “给模型的上下文摘要”与“给用户看的个人笔记”是两份独立内容。
- 用户可以从同一节点中的用户消息和 AI 消息里选择素材。
- 选择粒度包括整条消息、单轮或多轮问答、消息内的连续或不连续片段。

## 2. 子节点上下文的四种方案

### 方案 A：完整父会话

把父节点的全部消息作为子节点上下文。

- 优点：信息损失最少，实现直接。
- 缺点：节点层级越深，提示词越大；成本、延迟和噪声都会持续增加。
- 结论：不作为默认方案。

### 方案 B：父节点摘要 + 引用原文 + 问题描述

由用户维护一份父节点上下文摘要，创建子节点时再附上本次选择的原文和问题。

- 优点：上下文规模稳定，来源清楚，符合当前产品方向。
- 缺点：需要处理摘要缺失、过期和编辑冲突。
- 结论：当前首选方案，后续优先验证。

### 方案 C：用户筛选的原始消息 + 问题描述

不生成摘要，直接把用户筛选的若干原始问答或片段传给子节点。

- 优点：完全可控，可追溯，没有摘要失真。
- 缺点：用户操作成本较高，选择过多时仍会形成长上下文。
- 结论：适合作为方案 B 的高级选项或降级路径。

### 方案 D：模型自动检索相关上下文

系统从父会话中自动选择与新问题相关的内容。

- 优点：用户操作最少。
- 缺点：行为不透明，可能漏掉用户认为关键的信息，还需要额外检索与评估机制。
- 结论：不进入早期版本。

## 3. 当前摘要材料规则

背景摘要的材料是父节点完整会话，不再按当前轮次、摘录位置或最近消息裁剪。模型必须通读全文，并保留低频但有意义的概念、修正、结论、约束和未解决问题。

进入“整理上下文”模式后，用户选择的是需要原样传递的引用内容：

1. 选择一条用户提问或一条 AI 回答；
2. 选择连续的一轮或多轮问答；
3. 在单条消息中框选一个或多个片段；
4. 跨同一节点的多条消息收集不连续片段；
5. 在生成摘要前检查、移除和重新排序素材。

这些选择不决定背景摘要范围，只决定“引用原文”部分。背景摘要和引用原文继续作为两份独立内容传递。

## 4. 更新已有摘要

节点只有一份“当前生效摘要”。生成或重新生成时，模型始终读取该节点当前的完整会话，并用新的结构化结果替换旧摘要，不做局部素材合并。

- 用户决定何时生成，不在每轮聊天后自动更新；
- 已有摘要被覆盖前必须明确确认；
- 摘要生成后仍可手动编辑；
- 会话消息被新增、编辑或删除后，摘要标记为过期，提醒用户重新通读生成；
- 全局 Agent 只看到树摘要，不能直接改写节点摘要；摘要更新必须从节点内授权完整会话生成。

当前版本不提供摘要历史、差异比较或局部合并。这些能力只有在实际使用证明有必要时再加入。

## 5. 摘要缺失或过期时

创建子节点时，背景摘要是“父节点摘要 + 引用原文 + 问题描述”中的必填部分。如果摘要为空或已经过期，界面会明确提示用户重新生成，或者直接手动填写；没有摘要时不能进入后续步骤，也不会在用户不知情的情况下自动总结或扩充上下文。

当前流程不提供跳过摘要的分支。这样可以保证每个子节点都明确知道父节点整体讨论了什么，而不是只看到一段脱离上下文的摘录。

全局 Agent 的主题巡检属于另一种入口，但仍遵守同一结果结构：Agent 在读取完整节点后草拟必要背景，通过真实消息 ID 指定原文，并给出分支问题；用户审核通过后，三部分才会被冻结到新节点。消息 ID 不存在或画布版本变化时不执行。

## 6. 提示词预览

当前实现采用“每次确认”：创建子节点前按三个步骤确认摘要、引用原文和用户疑问，并在最后提供最终注入上下文的预览。这样用户能在创建前发现摘要遗漏、引用顺序或问题表述的问题。

按需展开、直接创建的轻量流程暂不启用，等真实使用数据表明三步确认过重后再评估。

## 7. 后续需要回答的问题

- 多段不连续选择采用“逐段加入素材篮”，还是支持系统级多选快捷键？
- 摘要是否需要固定结构，例如“背景、已确认结论、术语、未解决问题”？
- 重新生成完整摘要时，是否需要保留并提示用户核对人工修改？
- 是否确实需要摘要历史，以及要保存多少份、是否显示差异？
- 创建子节点时，问题描述在新节点创建前填写，这是当前流程的固定步骤。
- 如何显示 token 估算、隐私提示和被排除内容？

## 8. 推荐的验证顺序

1. 先验证用户是否真的频繁从原文创建分支；
2. 再加入连续片段和跨消息素材篮；
3. 验证完整节点摘要的生成、过期提醒和人工编辑是否足够；
4. 最后再评估自动检索与复杂版本管理是否必要。
