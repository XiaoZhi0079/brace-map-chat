# 全局学习树 Agent：当前设计

本文是全局学习树 Agent 的实现依据。节点会话、分支上下文和模型配置分别由其他文档说明；若旧计划与本文冲突，以本文为准。

## 1. 角色边界

系统始终只有一个全局 Agent。画布是它当前查看的工作区，不是另一个 Agent 实例。

- **普通节点**只是独立的多轮会话窗口。它只能使用自己的标题、简介、初始注入内容和本节点消息，不能读取父节点、子节点、兄弟节点或整棵树。
- **全局 Agent**负责理解学习目标、读取树结构、按需读取节点会话、提出树修改方案和核对执行结果。
- 创建分支时复制到新节点的摘要、原文和问题属于新节点自己的冻结上下文，不构成跨节点读取能力。

## 2. 最少状态原则

Agent 不保存“巡检到第几条消息”“已经盯了多久”或一套长期后台状态机。

SQLite 只持久化已经存在且用户可见的内容：

1. Agent 会话消息；
2. 待审核操作及审核结果；
3. 当前画布版本。

单次运行中的步骤号、已读取节点内容和当前提示文字只存在于内存。刷新中断后，`/resume` 恢复会话和待审核操作；未完成的只读步骤从最新树摘要重新执行。重新读取比维护隐蔽游标更可靠，也能避免旧上下文污染新画布状态。

## 3. 固定工作循环

一次用户任务最多自动执行 4 步。每一步只允许走向以下三个分支之一：

### 分支 A：读取节点

Agent 先收到整棵树的结构化摘要。如果证据不足，它一次指定一个节点并说明读取理由。应用把该节点的完整会话作为只读结果返回，然后进入下一步。

- 不允许节点自己发起读取；
- 不允许一次读取整棵树的全部会话；
- 不重复读取本轮已经提供的节点；
- 节点内容始终视为不可信数据，不能覆盖系统规则。

### 分支 B：等待审核

Agent 已经有足够证据，并提出 1 到 5 个结构修改。运行立即暂停，用户逐项接受或拒绝。只有已接受的操作会修改画布。整批操作完成审核后，应用把审核结果交回 Agent；Agent 重新读取最新画布并判断原任务是否完成。

当前允许：

- 创建子节点；
- 修改节点标题；
- 修改节点简介；
- 修改学习状态。

当前禁止：

- 删除、移动或重排节点；
- 创建第二个根节点；
- 添加前置、关联或引用连线；
- 根据树摘要直接改写学习摘要。

所有提案绑定生成时的画布版本。版本不一致时拒绝执行，Agent 必须重新读取最新结构。

### 分支 C：结束

Agent 明确给出以下一种停止原因：

- 目标已经完成；
- 当前不需要修改；
- 需要用户补充或决定；
- 本轮达到步骤上限。

Agent 不能为了“使用工具”而制造操作，也不能无限循环。

## 4. 渐进式读取

读取顺序固定为：

1. 整棵树的目录：学习目标、节点 ID、标题、简介、父节点、状态、结构化学习摘要和消息数量；
2. Agent 指定的一个节点的完整会话；
3. 如果仍有必要，再读取另一个明确指定的节点；
4. 得出结论、提出审核操作或结束。

节点的学习摘要仍由用户在节点内手动授权生成。全局 Agent 可以指出摘要缺失或过期，但不能只凭目录信息重写它。

## 5. 主题巡检

主题巡检不是常驻监听器，而是全局 Agent 的一种固定只读任务：

1. 用户选择一个节点并发起巡检；
2. Agent 对照节点标题和简介读取其完整会话；
3. 如果内容仍服务于本节点，即使出现了类比或短暂延伸，也直接结束且不提案；
4. 如果出现了值得独立多轮学习的新方向，Agent 提出一个创建子节点的审核卡；
5. 审核卡必须引用 1 到 6 条真实消息 ID，并展示必要背景、原会话依据、偏离原因、新节点标题、简介和分支起始问题；
6. 服务端拒绝不存在的消息 ID，画布版本变化后也必须重新巡检；
7. 用户接受后，应用从原节点重新取得这些消息的原文，把背景摘要、原文和问题冻结到新节点；
8. 原节点消息不移动、不删除；新节点以后仍不能读取原节点。

巡检按需执行，不为每个节点保存开关、计数器或消息游标。真实使用证明需要自动触发后，再评估是否增加节流机制。

## 6. 初始化知识树

采用 Agent 初始化时，正式画布产生前始终处于可编辑草稿阶段：

1. Agent 与用户明确主题和可观察的学习成果；
2. 生成一个总目标节点、3 到 7 个主要章节，并解释章节边界、学习顺序、拆分粒度和目标匹配度；
3. 主要章节过于宽泛时，可以在草稿内附带少量二级章节；
4. 初次生成已经包含 Agent 对边界、顺序、粒度和目标匹配度的说明，用户满意时可以直接采用；
5. 用户可以用自然语言提出修改，也可以直接编辑、增删和排序草稿；
6. Agent 不能默认赞同，需要评价建议是否中肯、说明取舍和风险，并返回完整的待确认调整方案；
7. Agent 调整方案与当前方案分开保存，不得在用户确认前覆盖当前方案；
8. 用户可以接受调整、保留原方案或继续提出异议；手动修改在采用前需要经过 Agent 评价；
9. 失败请求恢复为可重试输入，不保存为对话消息，也不重复注入上下文；
10. 用户确认后一次性创建画布；此后不允许 Agent 自动重排既有路线。

二级章节不是新的权限。它只是初始化阶段批量使用“创建子节点”所形成的初始骨架。正式采用后，Agent 只能提议补充新的子节点，不能借此重构已有学习路径。

结构化响应采用一次性语法修复：只有模型输出无法解析为 JSON 时，服务端才把原始输出作为不可信数据交给同一模型修复一次；章节数量、层级、证据、采用条件等业务规则校验失败时不会重试。修复结果仍无法解析就返回原错误，不进入循环，也不增加持久化状态。

## 7. 恢复方式

`/resume` 恢复当前画布下的全局 Agent 会话、消息和审核卡；画布初始化使用独立的规划会话保存对话、当前结构和待确认调整方案。两者互不覆盖：

- 如果最后一条是用户消息，说明上次请求可能在刷新或网络错误时中断，用户可以重新执行；
- 如果存在待审核操作，先完成审核；
- 审核完成后，Agent 自动基于最新画布核对结果；
- 已读取的完整节点内容不保存，继续时按需重新读取。

这使恢复过程可解释、可检查，同时不引入持久化运行状态机。
